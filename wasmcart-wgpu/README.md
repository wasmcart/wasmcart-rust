# wasmcart-wgpu

A [wgpu](https://wgpu.rs) backend for [wasmcart](https://github.com/wasmcart/wasmcart)
carts. It implements wgpu's `custom` backend traits over the WebGPU functions
a wasmcart host gives a cart as wasm imports (the emdawnwebgpu import set the
wasmcart SPEC freezes), so Rust carts and wgpu-based engines render through
the host's WebGPU with the ordinary wgpu API: no wasm-bindgen, no web-sys, no
JavaScript in the cart.

```rust
let gpu = wasmcart_wgpu::Gpu::new(640, 480).expect("no WebGPU");   // in wc_init
// gpu.device, gpu.queue, gpu.surface: plain wgpu
let frame = gpu.frame().unwrap();                                   // in wc_render
// ... render into frame.view, submit ...
gpu.present(frame);
```

See the "WebGPU carts, with wgpu" section of the wasmcart-rust README for the
rules the host imposes (nothing blocks; one canvas the host presents), how a
compatibility-mode device is described and filled in (honest limits and
downlevel flags, an emulated sRGB canvas, one-cube cube arrays), how to ask
for a core device, and what is not available.

Features:

- `alloc-exports` (default): export `wc_alloc` / `wc_free`, which the host's
  WebGPU glue allocates in cart memory with. Turn it off if the cart exports
  its own pair.
- `naga-ir`: accept `ShaderSource::Naga` modules (written out as WGSL in the
  cart; pulls in naga).

`src/ffi.rs` is generated by `scripts/gen-webgpu-ffi.mjs` from the webgpu.h of
the emdawnwebgpu release wasmcart pins (Dawn, BSD 3-Clause), and checks every
struct's layout at compile time against the table the host's glue reads cart
memory with.
